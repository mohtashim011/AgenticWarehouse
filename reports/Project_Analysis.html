1 The Repo Has 3 Parts

Everything in the repository falls into these three folders/files.

1. AutoWare/ — Web App

A full Django (Python) web dashboard. The "brain" where staff log in, manage products, approve requests, generate QR codes, and see charts. Uses SQLite locally, MySQL online.

2. QR_Scanner/ — Hardware + Vision

The physical side: ESP32-CAM firmware (.ino), conveyor Arduino code, and Python scripts (insert.py, delete.py) that read QR codes with OpenCV.

3. Orignal Code.txt

The first prototype — an old PHP insert script + a simple Python QR reader. It shows how the project started before moving to Django + MySQL. Reference only.

3 Part 2 — The Hardware (Is Hardware Attached? YES)

This is the physical automation. The code for it is real and present in the repo.

ESP32-CAM (AI-Thinker)

A tiny WiFi camera. Firmware QR_Scanner.ino connects to WiFi, runs a mini web server, and serves photos at /cam-hi.jpg. It even turns on its flash LED. Used to photograph QR codes.

Conveyor Belt + Arduino

conveyor.txt is Arduino code. It reads 2 analog/IR sensors (A0, A1) and drives 2 motors/relays (pins 11, 12). When a sensor sees an item, it runs the belt in a timed sequence.

Laptop / PC (the bridge)

Runs insert.py & delete.py using OpenCV + pyzbar. Pulls the camera image over WiFi, decodes the QR, and updates the online database.

WiFi Hotspot + Cloud Server

A phone hotspot connects the camera and laptop. The database + web app are hosted online on PythonAnywhere (MySQL), reached through an SSH tunnel.

Two scanning stations

Entry gate — insert.py

  • Camera photographs the QR as the item enters.
  • Reads name, batchno, productno.
  • Checks the product name is allowed, then inserts it into stock.
  • Writes a log: "Item Inserted".

Exit gate — delete.py

  • Camera photographs the QR as the item leaves.
  • Copies the record into "deleted products".
  • Writes a log: "Item Deleted".
  • Removes it from live stock.

4 How the System Works — Step by Step

The full journey of one product, from label to dashboard.

1

QR label is created

In the web app, the Manager generates a QR code holding name, batchno, productno. It is printed and stuck on the product.

Web app se QR code banta hai (naam, batch, product number) aur product par lagta hai.
2

Product goes on the conveyor

The item is placed on the belt. An IR sensor detects it and the Arduino runs the motor to move it forward under the camera.

Product belt par rakha jata hai; sensor detect karta hai; motor belt chalata hai.
3

ESP32-CAM takes a photo

The WiFi camera continuously serves images. The laptop pulls the latest photo over WiFi (e.g. http://192.168.x.x/cam-hi.jpg).

Camera photo leti hai; laptop WiFi se woh photo uthata hai.
4

Laptop decodes the QR

OpenCV + pyzbar read the QR from the photo and split it into name, batch, product number.

Laptop OpenCV se QR parh kar teen cheezein nikalta hai: naam, batch, product no.
5

Database is updated (via SSH tunnel)

Entry → the product is inserted into the online MySQL. Exit → it is moved to deleted and removed. A log row is added each time.

Online database (MySQL) update hoti hai: entry par add, exit par delete. Har dafa log banta hai.
6

Dashboard shows live status

Staff open the Django dashboard to see current stock, product logs, and charts (monthly/daily inserts & deletes). Requests and notifications flow between roles.

Dashboard par live stock, logs aur charts nazar aate hain; requests/notifications roles ke beech chalti hain.

6 What Is Pending / Missing

These gaps are exactly what your new research proposal is meant to solve.

Missing intelligence

  • No AI at all — everything is fixed rules, not smart decisions.
  • No multi-agent system — parts don't think or talk to each other.
  • No dynamic task allocation or path planning.
  • No reinforcement learning / IoT agent framework.

Weak points & robustness

  • Single point of failure — one server, one WiFi, one SSH tunnel. If any drops, all stops.
  • Hard-coded IP addresses & WiFi names (break easily on a new network).
  • No automated tests (tests.py are empty).
  • Only a conveyor — no autonomous transport robots.
  • Not resilient to power cuts / weak internet.
  • Exposed database password in the code (see Security).
Roman Urdu
Jo baaqi hai: Is mein koi AI nahi — sab kuch fixed rules par chalta hai. Koi multi-agent system, koi smart decision, koi path planning nahi. System ek server / ek WiFi par depend karta hai — woh band ho to poora system ruk jata hai. IP address hard-coded hain, tests nahi hain, aur database ka password code mein khula para hai (security issue). Yehi cheezein aap ka naya research proposal solve karega.

7 The Major Task of the Project

In one sentence — what the whole effort is really about.

Major task: Take this centralised, rule-based automated warehouse and upgrade it into a decentralised, intelligent multi-agent system — where each part (scanner, conveyor, inventory, transport) is a smart agent that decides, communicates, and cooperates — and then prove in a Python simulation that it is faster, scales better, and recovers from failures better than the current system.

! Important Security Warning

Your database & SSH password is written in plain text inside QR_Scanner/insert.py and delete.py, and the repository is public on GitHub. Anyone can read it. The SQL queries are also built by string-joining (SQL-injection risk).

What to do (soon)

  • Change / rotate that PythonAnywhere password immediately.
  • Move secrets into environment variables or a .env file (never commit them).
  • Remove the password from the old git history (or make the repo private).
  • Use parameterised SQL queries everywhere (some scripts still use f-strings).
Roman Urdu
Zaroori security warning: Aap ka database/SSH ka password code mein khula likha hua hai (insert.py aur delete.py) aur repo public hai — koi bhi parh sakta hai. Foran password change karein, secrets ko .env mein daalein, aur purani git history se hata dein (ya repo ko private kar dein).
