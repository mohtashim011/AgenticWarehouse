Checking the phone is on the same network

The two devices need matching addresses, not identical ones. Compare these.

This machine {{LAN_IP}}
Found with ipconfig in Command Prompt — read the IPv4 Address of the adapter that does not say "Media disconnected".
The phone Android: Settings, Network & internet, Wi-Fi, tap the connected network, then Advanced or Details.
iPhone: Settings, Wi-Fi, tap the small (i) beside the connected network.
What must match The phone's address must begin {{PREFIX}} and end in a different final number. Same first three, different last one — that is what being on one network looks like. If the phone shows something starting 172. or a completely different 10.x, it is on another network: usually mobile data or a guest Wi-Fi.
The quickest test of all Skip the numbers. Type the address at the top of this page into the phone's browser. If the warehouse loads, you are on the same network — that is the only thing the addresses were ever telling you.
This address is not permanent. The router hands it out and can hand out a different one after a restart, so a bookmark that worked last week may point nowhere. Re-open this page for the current address whenever the phone stops connecting.

Two things people expect to be true that are not

The phone and this machine share one IP They share a network, not an address. This machine is {{LAN_IP}}; the phone has a different address on the same Wi-Fi, which is exactly why it can reach this one. If the phone shows a 192.168.x.x or 10.x.x.x address in its Wi-Fi settings and this machine shows another in the same range, you are set up correctly.
The phone camera feeds this screen It does not, and nothing here streams video between the two. The phone runs the whole application itself and writes to the same database over the network, so a scan made on the phone appears on this machine's dashboard immediately. The phone is a second workstation, not a webcam.

If the phone cannot open it

The page loads but the camera will not start Browsers only grant camera access on a secure page. On a LAN address that means HTTPS, so the server has to be started with python app.py --https. Nothing else fixes it — it is a browser rule, not a setting in this application.
The browser warns about the certificate Expected, once. The certificate is generated on this machine and signed by nobody, because there is no certificate authority on a warehouse LAN. Choose Advanced and continue. It is the same machine you are reading this on.
The address does not load at all Usually the firewall on this machine, or guest Wi-Fi. Allow Python through the firewall for private networks, and check the phone is not on a guest network — most guest networks isolate devices from each other by design.
It worked yesterday and not today This machine's address is handed out by the router and can change when it reboots. Re-open this page for the current one, or give this machine a fixed address in the router.

The phone keeps its own camera list: it registers as its own station on the Cameras screen, because a camera id issued by one browser means nothing in another. Configure the phone's front and back cameras from the phone.
